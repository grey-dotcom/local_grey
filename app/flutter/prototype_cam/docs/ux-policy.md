## 1. 공통 운영 정책

### 촬영 원칙

실시간성 유지: 기기 내 앨범 호출(Image Picker) 불가. 오직 In-App 카메라로만 촬영 가능함.
위치 정보 증빙: 촬영 시 GPS 좌표를 메타데이터로 기록하여 현장 방문 사실을 백그라운드에서 증빙함.

### 워크플로우

자동 전환(Auto-Advance): 촬영 즉시 로컬에 임시 저장하고, 다음 업무 도안으로 자동 이동함. 이동 대상은 아래 촬영 후 이동 정책을 따름.

### 사용자 환경

장갑 모드(Gloved Mode): 버튼 최소 터치 영역 44×44pt 유지. 셔터 버튼은 80pt 이상 권장함.
저조도 대응(Low-Light): 어두운 현장을 대비하여 뷰파인더 내 자동 노출 조정 기능을 적용함.

## 2. 핵심 인터랙션 정책

### 2-1. 촬영 후 자동 이동 정책 (Auto-Advance)

촬영 완료 즉시 아래 우선순위 순서대로 다음 화면을 결정함.

일반 촬영(첫 촬영)인 경우, 현재 도안 이후 순서에서 아직 촬영되지 않은 첫 번째 도안으로 이동함. 미촬영 도안이 더 이상 없으면 마지막 도안에 머무르며 수행완료 버튼을 활성화함.

재촬영이고 아직 촬영되지 않은 필수 도안이 남아있는 경우, 전체 그룹에서 순서상 가장 앞에 있는 미촬영 필수 도안으로 이동함.

모든 필수 도안 촬영이 완료된 경우, 촬영 화면을 자동으로 종료(pop)하고 시작화면으로 복귀함.

| 시나리오 | 이동 대상 |
|---|---|
| 일반 촬영 + 미촬영 도안 있음 | 다음 미촬영 도안 |
| 일반 촬영 + 모든 필수 완료 | 촬영 화면 자동 종료 → 시작화면 |
| 재촬영 + 필수 미완료 | 첫 미촬영 필수 도안 |
| 재촬영 + 모든 필수 완료 | 촬영 화면 자동 종료 → 시작화면 |

### 2-2. 드롭다운 아코디언 정책

업무 도안 카드 내 안내문구(Contents) 영역은 기본 상태에서 1줄만 노출됨. 우측 Chevron(∨) 버튼 탭 시 아코디언 UI로 확장되어 전체 내용을 표시함. 확장 시 AnimatedSize(220ms, easeInOut) 애니메이션이 적용되며 Chevron 아이콘은 AnimatedRotation(220ms)으로 180도 회전함.

도안 간 이동 시 사용자가 마지막으로 설정한 드롭다운 상태(열림/닫힘)를 유지함.

## 3. 사진 업로드 & 수행완료 정책 [신규 v2.0]

### 3-1. 정책 목적

사진 누락으로 인한 서비스 품질 저하 및 클레임 방지, 수행완료 상태와 업로드 상태를 명확히 구분하여 사용자 혼란 최소화, 불안정한 네트워크 환경에서도 안정적인 업무 처리 보장.

### 3-2. 필수 / 선택 사진 정책

필수 사진은 모두 서버 업로드 완료되어야 수행완료 가능함. 필수 사진 누락 시 수행완료 불가.
선택 사진은 촬영된 경우 업로드 완료 시 서버에 저장되며, 촬영하지 않은 경우 수행완료에 영향 없음.

### 3-3. 촬영 모달 상태값 5종

촬영 업무 선택 모달(Task List Modal) 내 각 도안의 상태를 아래 5종으로 정의함.

완료: 사진 촬영 후 서버 업로드까지 완료된 경우. 체크 배지 + 회색 텍스트로 표시함.
진행중: 현재 포커스된 도안이 첫 촬영인 경우. 파란 테두리 + 파란 텍스트로 강조함.
대기: 촬영이 이루어지지 않은 업무 도안. 회색 번호 + 일반 텍스트로 표시함.
업로드중: 사진 촬영/재촬영 완료 후 큐에서 서버로 전송 중인 도안. 스피너 배지 + 연파랑 뱃지로 표시함. 촬영과 재촬영 모두 해당됨.
에러(재시도): 업로드 실패 상태. 뱃지 텍스트를 "재시도"로 표기하며 빨간 테두리 + 재시도 버튼을 노출함.

리프레시 정책: 업로드가 BE에서 완료되더라도 사용자가 별도 액션(리프레시)을 취하지 않는 한 앱 내 상태값은 이전 상태를 유지함. 실시간 동기화 없음.

### 3-4. 업로드 큐 정책

같은 도안을 여러 장 연속 촬영할 경우, 가장 마지막에 촬영한 사진만 큐에 유지함.
업로드 중인 사진은 완료/에러 여부와 무관하게 모달에서 "업로드중" 상태로 표기 유지함.

[FE/BE 논의 필요] 큐 처리 주체(FE 로컬 큐 vs BE 서버 큐) 및 재시도 API 방식(동일 endpoint 재호출 vs 별도 endpoint) 확정 필요.

### 3-5. 업로드 실패 정책

업로드 실패 사진은 로컬에 유지함. 사용자는 언제든 재시도 가능하며 실패 사진에 명확한 재시도 UI를 제공함.
재시도 가능 에러(네트워크 오류, 서버 일시 오류): 재시도 버튼 노출.
재시도 불가 에러(인증 만료, 잘못된 파일 형식): 오류 메시지 + 재촬영 유도만 표시함.

### 3-6. 오프라인 정책

오프라인 촬영 사진은 로컬 DB에 저장(queued 상태 유지). 네트워크 연결 시 자동 업로드. 앱 재실행 시에도 업로드 상태 유지.

### 3-7. 데이터 보존 정책

사용자가 촬영한 사진은 업로드 완료 전까지 로컬에 보존함. 서버 업로드 성공 시 서버 기준으로 관리하며 로컬 삭제함.

### 3-8. 어드민 업로드 사진 정책

어드민에서 업무 도안에 사진을 업로드한 경우, 사진촬영 화면이 "재촬영" 상태로 표시됨. 단, 사용자는 해당 정보를 화면 재진입(리프레시) 상황에서만 확인 가능함.

[BE 연동 필요] GET /api/v1/tasks/{taskId}/captures — 화면 재진입 시 어드민 업로드 사진 상태 조회.

## 4. 화면별 상세 기능

### 화면 1 — 시작화면 / 등록하기 (Task List Screen) [v2.0 변경]

**상단 구성**

업무 그룹별 도안 목록을 표시하며, 각 도안 카드에 업로드 상태 아이콘을 표시함.

도안 카드 상태 표시:
- 업로드 대기중(queued): 연파랑 배경 + 시계 아이콘 + "대기중" 텍스트
- 업로드중(uploading): 어두운 오버레이 + 스피너 + "업로드 중" 텍스트
- 업로드 완료(success): 체크 아이콘 + "촬영 완료" 텍스트
- 업로드 실패(error): 빨간 오버레이 + 새로고침 아이콘. 탭 시 재시도 바텀시트 노출.

**하단 버튼 3단계 전환**

필수 도안 미촬영 상태: [등록 완료] 버튼 disabled(회색). 탭 시 미촬영 안내 다이얼로그 노출.

필수 도안 촬영 완료 상태: [수행완료] 버튼 active(파랑). 사용자가 이 시점에 재촬영 가능함.
- [수행완료] 탭 + 업로드 완료 → 즉시 등록완료 처리.
- [수행완료] 탭 + 업로드 진행 중 → [등록 완료 - 업로드중] disabled 상태로 전환. 업로드 완료 시 자동 등록완료 처리.

[등록 완료 - 업로드중] 상태: 버튼 disabled + 스피너 표시. 업로드 완료 시 자동으로 등록완료 처리됨.

[BE 연동 필요] POST /api/v1/tasks/{taskId}/complete — 수행완료 API. 업로드 완료 감지 후 자동 호출.

### 화면 2 — 업무 촬영 메인 (Capture Screen)

**상단 정보 영역 (Guide Card)**

업무 그룹 타이틀: 현재 소속된 그룹명을 상단 중앙에 표시함.
진행 상태 배지: [필수|선택] / [현재 순서] / [전체 수] 형태. 배지 height 26px 고정.
업무 안내문구: 기본 1줄 노출. Chevron 탭 시 전체 내용 아코디언 확장.
페이지네이션: 현재 도안(파란 원형 24px), 완료 도안(파란 체크 원형 20px), 미촬영(회색 점 8px).

**카메라 뷰 영역**

조작 안내 힌트 Pill: 미촬영 도안 → "좌우로 밀거나 화살표를 눌러 이동할 수 있어요". 재촬영 도안 → "저장된 사진이 있어요. 다시 촬영하려면 재촬영 버튼을 선택하세요."

스와이프 제스처: 좌(←) 다음 도안, 우(→) 이전 도안. 임계값 40px. 순환 스와이프 지원(마지막 ↔ 첫 번째).

업로드 인디케이터: 현재 도안이 uploading 또는 queued 상태일 때 우측 상단에 "업로드 중" 표시.

**하단 액션 영역**

셔터 버튼: 단일 탭으로 촬영 실행. 촬영 완료 도안 진입 시 '재촬영' 텍스트로 전환.
미리보기 썸네일: 재촬영 모드에서만 노출. 크기 52×52px. 탭 시 전체화면 확대.
위치 계산: 화면너비 ÷ 2 − 42px(셔터반지름) − 50px(간격) − 52px(썸네일크기).

**촬영 완료 말풍선 토스트**

모든 촬영 완료 후 표시. fadeIn 200ms → 유지 1100ms → fadeOut 200ms = 총 1500ms.

### 화면 3 — 촬영 업무 선택 모달 (Task List Modal) [v2.0 변경]

진입: 카메라 화면 우측 상단 리스트 아이콘 탭 시 바텀 시트 모달로 노출됨.

상태값 5종 표시:
- 완료: 체크 배지 + 회색 테두리 + "완료" 뱃지
- 진행중: 파란 배경 + 파란 테두리 + "진행중" 뱃지
- 대기: 번호 배지 + 회색 테두리 + "대기" 뱃지
- 업로드중: 스피너 배지 + 연파랑 테두리 + "업로드중" 뱃지
- 에러: 빨간 테두리 + "재시도" 뱃지 + 재시도 버튼

업로드중 도안 탭: 재촬영 진입 허용(isRecaptureMode=true로 진입).
에러 도안 탭: 재시도 버튼 → retryUpload() 호출 후 모달 닫힘.

## 5. 예외 처리 정책

필수 촬영 누락: 수행완료 버튼이 비활성 처리됨. 탭 시 미촬영 안내 다이얼로그 노출.

카메라 권한 거부: 앱 진입 시 권한 확인. 거부 상태이면 시스템 설정 유도 안내 화면 노출. 재시도 버튼 탭 시 권한 요청 재실행.

업로드 실패: 촬영 데이터는 로컬에 우선 저장 후 백그라운드에서 서버 전송 시도. 실패 시 도안 카드 및 촬영 모달에 에러 UI 노출. 재시도 가능 에러는 재시도 버튼, 재시도 불가 에러는 재촬영 유도.

저장 공간 부족: 촬영 전 기기 용량 확인. 부족 시 촬영 기능 비활성화 및 알림 팝업 노출.

## 6. FE/BE 논의 필요 항목 [v2.0 신규]

아래 항목은 정책 방향은 확정되었으나 구현 방식을 FE/BE 협의 후 결정해야 함.

업로드 큐 처리 주체: FE 로컬 큐 vs BE 서버 큐.
재시도 API 방식: 동일 endpoint(POST /api/v1/captures) 재호출 vs 별도 endpoint.
수행완료 자동 처리 동기화 방식: FE 폴링 vs 웹소켓 vs 업로드 응답에 포함.
에러 코드 분류 정책: 재시도 가능(408/500/502/503/504) vs 재시도 불가(400/401/403/415) — BE 확정 후 api_service.dart의 _isRetryableStatusCode 업데이트.

## 7. 미구현 항목 (개발 예정)

아래 항목은 정책은 확정되었으나 현재 Web Prototype에는 미반영 상태이며, iOS/Android 네이티브 앱 개발 시 구현 예정임.

GPS 메타데이터 기록: native_camera_service.dart 스텁으로 인터페이스만 정의됨.
그룹 전환 화면(Transition Screen): 필수 도안 전체 완료 시 자동 진입 화면.
그룹 이동 오버레이: 이전 그룹으로 즉시 이동하는 하단 오버레이.
업로드 완료 자동 처리 API 연동: capture_provider.dart의 _triggerCompleteApi() stub 구현.
어드민 업로드 사진 상태 조회: loadTasks() 초기화 시 서버 상태 반영.
수행전/후 사진 촬영 화면: 직전과 현재 사진 여러 장 + 텍스트 입력 기능 (다음 스펙으로 이관).
오프라인 자동 재업로드: ConnectivityResult 감지 → queued 상태 자동 uploading 전환 (웹 프로토타입 한계).
