## 1. 기능 개요

운영자가 키퍼로부터 접수된 이슈(파손·기기 불량·오염·비품 부족 등)를 한 곳에서
확인하고, 완료 처리 또는 보류 처리할 수 있도록 제공하는 위젯이다.

| 항목 | 내용 |
|---|---|
| 위젯명 | 처리 필요 |
| 데이터 대상 | 전체 이슈(IssueReport) — 날짜 제한 없음 |
| 주요 기능 | 상태 필터링 / 완료 처리 / 보류 처리 / 재접수 / 이슈 취소 |
| 최대 노출 카드 수 | 웹 기준 3개 (초과 시 내부 스크롤) |
| 정렬 기준 | 접수 일시(reportedAt) — 서버 응답 순 |

## 2. 화면 구성

### 2-1. 레이아웃

- 대시보드 콘텐츠 영역에 배치 (FeedWidget과 나란히 또는 세로 배치, 반응형)
- 흰색 배경, 8px 둥근 모서리, 1px #EEEEEE 테두리
- 헤더 영역(타이틀·버튼·필터 탭)과 카드 리스트 영역으로 구성

### 2-2. 헤더 영역

| 요소 | 내용 |
|---|---|
| 타이틀 | "처리 필요" — fontSize 20, fontWeight 700 |
| ⓘ 아이콘 | 위젯 기능 안내 툴팁 (클릭 시 팝업) |
| 이슈 생성 버튼 | 우측 배치. 클릭 시 이슈 생성 플로우 연결 |
| 필터 탭 | 4종 가로 나열 (아래 §2-3 참고) |
| 패딩 | 데스크탑 24px / 모바일 16px |

### 2-3. 필터 탭 (4종)

| 탭 키 | 라벨 | 포함 상태값 |
|---|---|---|
| ALL | 전체 | 전체 이슈 |
| ISSUE | 이슈 | REPORTED (접수됨) |
| HOLD | 보류 | HOLD |
| COMPLETED | 완료 | RESOLVED |

- 활성 탭: 파란 배경(#E3F2FD), 텍스트 #304FFE, 카운트 배지 흰색
- 비활성 탭: 텍스트 rgba(0,0,0,0.60), 카운트 숫자 인라인 표시
- 카운트 상한: 99+
- 탭 줄바꿈: flexWrap wrap 허용 (좁은 화면 대응)

### 2-4. 카드 리스트

- 카드 간 gap: 8px
- 패딩: 상하 16px / 좌우 24px (모바일 16px)
- 카드 수 ≤ 3: 자연 높이
- 카드 수 > 3: 첫 3개 카드 실측 높이 합산으로 maxHeight 고정 + 내부 스크롤
- 모바일 1열 탭 구간: 높이 제한 없음

### 2-5. 카드 구성 요소

**공통 상단 행**
- 좌측 색상바: 모든 이슈 상태 #FF1744 (빨간) — 이슈는 항상 주의 요구
- 배지 행: NEW 배지 + 이슈타입 배지 + 상태 배지 (RESOLVED 시 순서 반전: 상태→이슈타입)
- 우측: 접수 일시(reportedAt) + 상세 보기 화살표 버튼

**이슈타입 배지**
- 배경 #FEEBEE, 텍스트 #FF1744, ! 아이콘 포함
- 이슈타입 한글 라벨: 파손 / 기기 작동 불량 / 오염 / 비품 부족 / 문제 발생 / 기타

**상태 배지 색상**

| 상태 | 한글 | 배경 | 텍스트 |
|---|---|---|---|
| REPORTED | 접수됨 | #E3F2FD | #1565C0 |
| HOLD | 보류 | #FEEBEE | #FF1744 |
| RESOLVED | 완료 | #E8F5E9 | #2E7D32 |
| CANCELED | 취소 | #F5F5F5 | #9E9E9E |

**카드 본문**
- 보고자명(reporterName): fontSize 16, fontWeight 700
- 위치: roomGroupName ㆍ roomName (핀 아이콘 포함)
- 이슈 설명 알림박스: #FEEBEE 배경, #D50000 텍스트, ! 아이콘
- 사진(photoUrls): 있을 때만 노출 (최대 3장 그리드)
- 처리 코멘트(processingComment): 있을 때만 회색 박스로 노출
- 처리 예정일(scheduledDate): 있을 때만 달력 아이콘과 함께 노출

**상태별 액션 버튼 구성**

| 상태 | 왼쪽 버튼 | 오른쪽 버튼 |
|---|---|---|
| REPORTED (접수됨) | 보류 (outlined) | 완료 (primary-contained) |
| HOLD (보류) | 취소 (outlined) | 재접수 (primary-contained) |
| RESOLVED (완료) | 없음 | — |
| CANCELED (취소) | 없음 | — |

**완료 상태 카드 표시**
- 배지 행 + 본문 영역: opacity 0.4 (흐리게 표시)
- 배지 순서 반전: 상태 배지(완료, 체크 아이콘) → 이슈타입 배지

## 3. 사용자 시나리오

### 시나리오 A — 정상 조회
```
1. 운영자가 대시보드에 접속한다.
2. 처리 필요 위젯에 전체 이슈 카드들이 로드된다.
3. 기본 탭은 "전체"로 설정된 상태로 모든 이슈가 표시된다.
4. 운영자는 각 카드의 이슈타입 배지와 접수 일시를 확인해 처리 우선순위를 판단한다.
```

### 시나리오 B — 이슈 완료 처리
```
1. 운영자가 REPORTED(접수됨) 상태 카드의 "완료" 버튼을 클릭한다.
2. 확인 팝업이 나타난다: "선택하신 이슈를 완료 처리하시겠습니까?"
3. 확인 선택 시 해당 이슈가 RESOLVED(완료) 상태로 전환된다.
4. 카드가 완료 상태 디자인(opacity 0.4, 체크 배지)으로 변경된다.
5. KPI 카드의 미해결 이슈 수치가 즉시 갱신된다.
```

### 시나리오 C — 이슈 보류 처리
```
1. 운영자가 REPORTED(접수됨) 상태 카드의 "보류" 버튼을 클릭한다.
2. 확인 팝업이 나타난다: "선택하신 이슈를 보류 처리하시겠습니까?"
3. 확인 선택 시 해당 이슈가 HOLD(보류) 상태로 전환된다.
4. 보류 탭 카운트가 즉시 증가한다.
```

### 시나리오 D — 보류 이슈 재접수
```
1. 운영자가 HOLD(보류) 상태 카드의 "재접수" 버튼을 클릭한다.
2. 확인 팝업이 나타난다: "선택하신 이슈를 재접수 처리하시겠습니까?"
3. 확인 선택 시 해당 이슈가 REPORTED(접수됨) 상태로 전환된다.
4. 이슈 탭 카운트가 즉시 증가한다.
```

### 시나리오 E — 보류 이슈 취소
```
1. 운영자가 HOLD(보류) 상태 카드의 "취소" 버튼을 클릭한다.
2. 확인 팝업이 나타난다: "선택하신 이슈를 취소하시겠습니까? 취소된 이슈는 복구할 수 없습니다."
3. 확인 선택 시 해당 이슈가 CANCELED(취소) 상태로 전환된다.
```

### 시나리오 F — 필터 탭 사용
```
1. 운영자가 "보류" 탭을 클릭한다.
2. HOLD 상태 이슈만 필터링되어 표시된다.
3. 운영자는 보류 중인 이슈의 처리 방향(재접수 또는 취소)을 결정한다.
```

### 시나리오 G — 지점 필터 적용 시
```
1. 운영자가 상단 탭에서 특정 지점을 선택한다.
2. 처리 필요 위젯의 카드가 해당 지점 이슈만으로 즉시 갱신된다.
3. 모든 필터 탭 카운트도 해당 지점 기준으로 재계산된다.
```

### 시나리오 H — 위젯 OFF
```
1. 운영자가 위젯 설정에서 처리 필요를 OFF한다.
2. 위젯 전체가 화면에서 사라지고 나머지 위젯이 재배치된다.
3. 모바일 탭 구간에서는 세그먼트 탭에서 '처리필요' 탭도 함께 제거된다.
```

## 4. 예외 케이스 (Edge Case)

| 상황 | 사용자 경험 |
|---|---|
| 이슈가 전혀 없음 | "조회된 일감이 없습니다." 문구 중앙 표시 |
| 선택한 필터 탭에 해당 이슈 없음 | "조회된 일감이 없습니다." 문구 중앙 표시 |
| 데이터 로딩 중 | "조회된 일감이 없습니다." 표시 (로딩 완료 후 갱신) |
| 카드 수 > 3 | 첫 3개 기준 maxHeight 고정 + overflowY auto |
| photoUrls 빈 배열 | 사진 영역 미노출 |
| processingComment null | 처리 코멘트 박스 미노출 |
| scheduledDate null | 처리 예정일 행 미노출 |
| 완료된 이슈 — 액션 버튼 | 버튼 미노출. 읽기 전용 상태. |

## 6. 디자인 요구사항

### 위젯 외곽
- 배경 흰색, border-radius 8px, outline 1px #EEEEEE
- overflow hidden

### 헤더
- 데스크탑 padding: 24px 24px 18px / 모바일: 16px 16px 12px
- 타이틀과 필터 탭 사이 gap 16px

### 필터 탭
- 활성: bg #E3F2FD, 텍스트 #304FFE, 카운트 배지 흰색 배경 #2962FF 텍스트
- 비활성: 텍스트 rgba(0,0,0,0.60)
- flexWrap: wrap (좁은 화면 2줄 허용)
- 카운트 상한: `count > 99 ? '99+' : count`

### 좌측 색상바
- 모든 이슈 상태: #FF1744 (빨간) — 이슈는 항상 주의 요구 색상 유지

### 상태 배지 (flexWrap wrap 적용)
- 컨테이너: flexWrap wrap / overflow visible
- 배지 개별: whiteSpace nowrap / flexShrink 0
- 완료 상태: 상태 배지(체크 아이콘 포함) → 이슈타입 배지 순서
- 그 외: 이슈타입 배지 → 상태 배지 순서

### 이슈 설명 알림박스
- 배경 #FEEBEE, 텍스트 #D50000
- ! 아이콘 + 설명 텍스트 flexRow

### 처리 코멘트 박스
- 배경 #F5F5F5, outline 1px #EEEEEE
- 상단 레이블: "처리 코멘트" (fontSize 11, color rgba(0,0,0,0.38))

### 액션 버튼
- 완료 / 재접수: primary-contained (#1976D2)
- 보류 / 취소: neutral-outlined (border rgba(0,0,0,0.23))
- 모바일 높이 30px / 데스크탑 36px
- 모든 버튼: ConfirmModal 선행 (error variant — 파괴적 액션)

### 완료 상태 카드 opacity
- 배지 행 + 본문 전체: opacity 0.4

### 높이 정책
- 카드 수 > 3: ResizeObserver로 첫 3개 실측 → maxHeight = 합산 높이 + gap(8×2) + 패딩(32)
- 측정 전 opacity 0 → 측정 완료 후 1 (깜빡임 방지)

### 반응형
- 웹: 위젯 콘텐츠 영역 padding 24px
- 모바일: padding 16px, 높이 제한 없음

### 접근성
- ⓘ 버튼: title "처리 필요 안내"
- 이슈 생성 버튼: 명시적 텍스트 포함
