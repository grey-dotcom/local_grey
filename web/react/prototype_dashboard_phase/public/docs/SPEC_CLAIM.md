## 0. 클레임 처리 흐름 (73차 확정)

> **고객사(투숙객 등)가 클레임을 등록하면, 파트너사(운영자)가 인정 또는 이의제기로 처리하여 종결하는 구조.**

```
고객사: 클레임 등록
         ↓
처리 대기(PENDING) — 미확인 클레임에 포함
         ↓ 파트너사(운영자) 검토
         ├→ 인정(ACCEPTED 인정완료)       : 클레임 종결 — 미확인 제외
         └→ 이의제기(DISPUTED 이의제기)   : 클레임 종결 — 미확인 제외
                  ↓ 후속 처리 완료 시
              이의제기 후속 처리 완료(DISPUTE_COMPLETED)
```

- 이의제기(DISPUTED)는 파트너사가 처리를 완료한 종결 상태다. "이의제기 진행 중"이 아니다.
- 이의제기 후 후속 업무(신규 일감 생성 등)가 발생할 수 있으며, 이를 모두 마친 상태가 DISPUTE_COMPLETED다.

## 1. 기능 개요

파트너사(운영자)가 고객으로부터 접수된 클레임(청소 상태 불량·시설 불만·서비스 미흡 등)을
인정 처리하거나 이의를 제기할 수 있도록 제공하는 위젯이다.

| 항목 | 내용 |
|---|---|
| 위젯명 | 클레임 |
| 데이터 대상 | 전체 클레임(ClaimReport) — 날짜 제한 없음 (미처리 클레임 전체 표시) |
| 주요 기능 | 상태 필터링 / 인정 처리 / 이의 제기 |
| 최대 노출 카드 수 | 웹 기준 3개 (초과 시 내부 스크롤) |
| 정렬 기준 | 오래된 순(reportedAt ASC) — 가장 오래된 미처리 클레임 먼저 표시 |

## 2. 화면 구성

### 2-1. 레이아웃

- 대시보드 콘텐츠 영역에 배치 (FeedWidget·IssueWidget과 함께 반응형 배치)
- 흰색 배경, 8px 둥근 모서리, 1px #EEEEEE 테두리
- 헤더 영역(타이틀·버튼·필터 탭)과 카드 리스트 영역으로 구성

### 2-2. 헤더 영역

| 요소 | 내용 |
|---|---|
| 타이틀 | "클레임" |
| ⓘ 아이콘 | 위젯 기능 안내 툴팁 (클릭 시 팝업) |
| 클레임 등록 버튼 | 우측 배치. 클릭 시 클레임 등록 플로우 연결 |
| 필터 탭 | 5종 가로 나열 (아래 §2-3 참고) |
| 패딩 | 데스크탑 24px / 모바일 16px |

### 2-3. 필터 탭 (5종)

| 탭 키 | 라벨 | 포함 상태값 | 설명 |
|---|---|---|---|
| ALL | 전체 | 전체 클레임 | |
| PENDING | 처리대기 | PENDING(처리 대기) | 파트너사 미처리 |
| DISPUTED | 이의제기 | DISPUTED(이의제기) ⚠️ mock 임시 키 | 파트너사 이의제기 처리 완료(종결) |
| ACCEPTED | 인정완료 | ACCEPTED(인정완료) ⚠️ mock 임시 키 | 파트너사 인정 처리 완료(종결) |
| DISPUTE_COMPLETED | 이의제기 후속 처리 완료 | DISPUTE_COMPLETED ⚠️ mock 임시 키 | 이의제기 후 후속 처리까지 완료(종결) |

- 활성 탭: 파란 배경, 텍스트 강조, 카운트 배지 흰색
- 비활성 탭: 텍스트 흐리게, 카운트 숫자 인라인 표시
- 카운트 상한: 99+
- 탭 줄바꿈: 좁은 화면에서 2줄 허용 (탭 5종)

### 2-4. 카드 리스트

- 카드 간 간격: 8px
- 패딩: 상하 16px / 좌우 24px (모바일 16px)
- 카드 수 ≤ 3: 자연 높이
- 카드 수 > 3: 첫 3개 카드 실측 높이 합산으로 최대 높이 고정 + 내부 스크롤
- 모바일 1열 탭 구간: 높이 제한 없음
- 정렬: 오래된 순 (가장 오래된 클레임 먼저) — 미처리 클레임 적체 방지

### 2-5. 카드 구성 요소

**공통 상단 행**

- 좌측 색상바:
  - 미처리(PENDING): 빨간색 — 파트너사 처리 필요
  - 종결(DISPUTED·ACCEPTED·DISPUTE_COMPLETED): 회색 — 처리 완료
- 배지 행: NEW 배지 + 상태 배지
- 우측: 접수 일시(reportedAt) + 상세 보기 화살표 버튼

**상태 배지**

| 상태 | 한글 | 종결 여부 |
|---|---|---|
| PENDING | 처리대기 | 미처리 |
| DISPUTED ⚠️ | 이의제기 | 종결 |
| ACCEPTED ⚠️ | 인정완료 | 종결 |
| DISPUTE_COMPLETED ⚠️ | 이의제기 후속 처리 완료 | 종결 |

⚠️ ACCEPTED·DISPUTED·DISPUTE_COMPLETED는 mock 임시 키. BE 키 확정 후 교체.

**카드 본문**
- 보고자명(reporterName): 클레임 특성상 "투숙객" 등 역할명 표시
- 위치: roomGroupName · roomName (핀 아이콘 포함)
- 클레임 설명 알림박스: 강조 배경색, 느낌표 아이콘
- 사진(photoUrls): 있을 때만 노출 (최대 3장 그리드)
- 처리 코멘트(comment): 있을 때만 회색 박스로 노출

**상태별 액션 버튼 구성**

| 상태 | 왼쪽 버튼 | 오른쪽 버튼 |
|---|---|---|
| PENDING (처리대기) | 이의제기 | 인정 |
| DISPUTED (이의제기) ⚠️ | 없음 (이의제기 처리 완료 — 종결) | — |
| ACCEPTED (인정완료) ⚠️ | 없음 (읽기 전용) | — |
| DISPUTE_COMPLETED (이의제기 후속 처리 완료) ⚠️ | 없음 (읽기 전용) | — |

**종결 상태 카드 표시**
- ACCEPTED·DISPUTED·DISPUTE_COMPLETED 상태: 카드 전체 흐리게 표시 (opacity 낮춤)
- 클레임 종결 = 인정 처리 또는 이의제기 처리 완료

## 3. 사용자 시나리오

### 시나리오 A — 정상 조회
```
1. 운영자가 대시보드에 접속한다.
2. 클레임 위젯에 전체 클레임 카드들이 오래된 순으로 로드된다.
3. 기본 탭은 "전체"로 설정된 상태로 모든 클레임이 표시된다.
4. 운영자는 가장 상단에 표시된 오래된 클레임부터 처리를 시작한다.
5. 클레임 설명 알림박스를 통해 고객 불만 내용을 파악한다.
```

### 시나리오 B — 인정 처리
```
1. 운영자가 처리대기(PENDING) 상태 카드의 "인정" 버튼을 클릭한다.
2. 확인 팝업이 나타난다.
3. 확인 선택 시 해당 클레임이 인정완료(ACCEPTED) 상태로 전환된다. 클레임 종결.
4. 카드가 종결 상태 디자인(흐리게 표시, 체크 배지)으로 변경된다.
5. KPI 카드의 미확인 클레임 수치가 즉시 갱신된다.
```

### 시나리오 C — 이의 제기
```
1. 운영자가 처리대기(PENDING) 상태 카드의 "이의제기" 버튼을 클릭한다.
2. 확인 팝업이 나타난다.
3. 확인 선택 시 해당 클레임이 이의제기(DISPUTED) 상태로 전환된다. 클레임 종결.
4. 카드 상태 배지가 "이의제기"로 변경되고 액션 버튼이 사라진다.
5. KPI 카드의 미확인 클레임 수치가 즉시 갱신된다.
6. 이의제기로 인한 후속 업무(신규 일감)가 별도로 생성될 수 있다.
```

### 시나리오 D — 필터 탭으로 처리대기 건 집중 조회
```
1. 운영자가 "처리대기" 탭을 클릭한다.
2. PENDING 상태 클레임만 필터링되어 표시된다.
3. 운영자는 미처리 클레임에 집중하여 인정 또는 이의제기를 처리한다.
```

### 시나리오 E — 지점 필터 적용 시
```
1. 운영자가 상단 탭에서 특정 지점을 선택한다.
2. 클레임 위젯의 카드가 해당 지점 클레임만으로 즉시 갱신된다.
3. 모든 필터 탭 카운트도 해당 지점 기준으로 재계산된다.
```

### 시나리오 F — 위젯 OFF
```
1. 운영자가 위젯 설정에서 클레임을 OFF한다.
2. 위젯 전체가 화면에서 사라지고 나머지 위젯이 재배치된다.
3. 모바일 탭 구간에서는 세그먼트 탭에서 '클레임' 탭도 함께 제거된다.
```

## 4. 예외 케이스

| 상황 | 사용자 경험 |
|---|---|
| 클레임이 전혀 없음 | "조회된 클레임이 없습니다." 문구 중앙 표시 |
| 선택한 필터 탭에 해당 클레임 없음 | "조회된 클레임이 없습니다." 문구 중앙 표시 |
| 데이터 로딩 중 | "조회된 클레임이 없습니다." 표시 (로딩 완료 후 갱신) |
| 카드 수 > 3 | 첫 3개 기준 최대 높이 고정 + 내부 스크롤 |
| photoUrls 빈 배열 | 사진 영역 미노출 |
| comment null | 처리 코멘트 박스 미노출 |
| DISPUTED 상태 | 이의제기 처리 완료(종결) 상태로 표시. 추가 버튼 없음. |
| ACCEPTED·DISPUTE_COMPLETED 상태 | 읽기 전용. 인정 처리 후 취소 불가. |

## 6. 디자인 요구사항

### 위젯 외곽
- 배경 흰색, border-radius 8px, outline 1px #EEEEEE
- overflow hidden

### 헤더
- 데스크탑 padding: 24px 24px 18px / 모바일: 16px 16px 12px
- 타이틀과 필터 탭 사이 gap 16px

### 필터 탭
- 활성: 파란 배경(#E3F2FD), 텍스트 #304FFE, 카운트 배지 흰색
- 비활성: 텍스트 rgba(0,0,0,0.38)
- flexWrap: wrap (탭 5종이므로 좁은 화면 2줄 허용)
- 카운트 상한: 99+

### 좌측 색상바 기준
| 조건 | 색상 | 의미 |
|---|---|---|
| PENDING (처리대기) | 빨간색 | 파트너사 미처리 |
| DISPUTED (이의제기) ⚠️ | 회색 | 종결 |
| ACCEPTED (인정완료) ⚠️ | 회색 | 종결 |
| DISPUTE_COMPLETED (이의제기 후속 처리 완료) ⚠️ | 회색 | 종결 |

### 종결 상태 카드
- ACCEPTED·DISPUTED·DISPUTE_COMPLETED: 배지 행 + 본문 전체 흐리게 표시 (opacity 낮춤)

### 액션 버튼
- 인정: primary-contained
- 이의제기: outlined (빨간 테두리)
- 두 버튼 모두: 확인 팝업 선행

### 높이 정책
- 카드 수 > 3: ResizeObserver로 첫 3개 실측 → maxHeight 고정
- 측정 전 숨김 → 측정 완료 후 표시 (깜빡임 방지)

### 반응형
- 웹: 위젯 콘텐츠 영역 padding 24px
- 모바일: padding 16px, 높이 제한 없음
