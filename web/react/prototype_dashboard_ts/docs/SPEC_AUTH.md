## 1. 개요

모든 화면 진입 전에 선행 적용되는 인증·인가 공통 미들웨어 정책.

| 항목 | 내용 |
|---|---|
| 적용 범위 | 대시보드 전체 라우트 |
| 구현 위치 | middleware.ts (Next.js middleware) |
| 프로토타입 상태 | 인증: 로그인 상태 유무 확인만 구현. 유효성 검증 미구현. |

## 2. 인증 (Authentication)

### 2-1. 플로우

```
요청 진입
  ↓
로그인 상태 확인 (토큰 존재 여부)
  ├── 토큰 있음 → 대시보드 진입 허용
  └── 토큰 없음 → /login 리다이렉트
```

### 2-2. 프로토타입 vs 실서비스

| 구분 | 프로토타입 (현재) | 실서비스 전환 시 |
|---|---|---|
| 토큰 확인 | 존재 여부만 확인 | 유효성 검증 추가 (만료·조작 여부) |
| 구현 위치 | middleware.ts | middleware.ts 또는 로그인 API 응답 처리 단계 |

### 2-3. 관련 BE 에러 키

| 상황 | BE 에러 키 | 화면 처리 |
|---|---|---|
| 토큰 만료 | `Exception.body.TIMEOUT_SIGN_IN` | /login 리다이렉트 |
| 위조된 토큰 | `Exception.body.INVALID_SIGNATURE_TOKEN` | /login 리다이렉트 |
| 유효하지 않은 토큰 | `Exception.body.INVALID_TOKEN` | /login 리다이렉트 |
| 인증 필요 | `Exception.body.AUTH_REQUIRED` | /login 리다이렉트 |
| 중복 로그인 | `Exception.body.DUPLICATE_LOGIN` | 팝업 후 /login 리다이렉트 |
| 계정 정지 | `Exception.body.SUSPENDED_ACCOUNT` | 팝업 후 /login 유지 |

## 3. 인가 (Authorization)

### 3-1. 플로우

```
로그인 성공
  ↓
로그인 응답에서 역할(role) 정보 수신
  ↓
역할 기준으로 접근 가능한 지점 목록 서버에서 필터링 후 제공
  ↓
화면: 서버 응답 지점 목록 그대로 표시 (클라이언트 필터링 없음)
```

### 3-2. 승인 대기 처리

로그인은 됐지만 워크스페이스 접근 승인이 없는 상태.

```
로그인 성공 + 역할 = NONE (승인 대기)
  ↓
대시보드 진입 차단
  ↓
/login 화면 유지
```

| 구분 | 프로토타입 (현재) | 실서비스 전환 시 |
|---|---|---|
| 승인 대기 차단 | 화면 진입 시점 이중 처리 중 | 로그인 처리 단계에서 역할 기반 차단 활성화 |
| 역할 정보 | 미확정 | 로그인 응답에 role 포함 필요 |
| 지점 목록 | 클라이언트 처리 | 서버에서 역할 기준 필터링 후 제공 |

관련 FE 라벨 키: `Enums.WorkspaceStaffRegistrationType.NONE` = "요청 승인 대기"

### 3-3. 역할별 권한

| 역할 키 | 한글 | 접근 범위 |
|---|---|---|
| `SUDO` | 소유주 | 워크스페이스 전체 |
| `ADMIN` | 총괄 관리자 | 워크스페이스 내 전체 지점 |
| `MANAGER` | 관리자 | 배정된 지점만 |
| `NONE` | 요청 승인 대기 | 접근 불가 |

관련 BE 에러 키: `Exception.body.INVALID_HEADQUARTER_ACCESS` — 본사 접근 권한 없음

## 4. 예외 처리

### 4-1. 워크스페이스 전환

```
워크스페이스 전환 이벤트 발생
  ↓
초기화 대상:
  - 선택된 지점 (roomGroupIds: [])
  - 현재 화면 상태 (탭·필터·스크롤)
  ↓
새 워크스페이스 기준으로 지점 목록 재요청 및 재구성
```

### 4-2. 로그아웃

```
로그아웃 실행
  ↓
초기화: 인증 토큰, 역할 정보, 서버 데이터 캐시
유지: 로컬 저장 환경 정보 (재로그인 시 복원 목적)
  ↓
/login 리다이렉트
```

로컬 유지 항목 (localStorage):
- 위젯 설정 ON/OFF 상태
- 지점 선택 필터 ID 목록 (`roomGroupIds: string[]`)

> STATUS_POLICY.md §8-8 참고: 이 두 항목만 로컬 저장. KPI 수치·지점 상세 정보 등 서버 데이터는 저장하지 않음.

### 4-3. 운영 중 인가 변경

운영 중 지점 접근 권한이 삭제된 경우.

```
해당 지점 데이터 API 호출
  ↓
403 또는 권한 없음 에러 수신
  ↓
접근 불가 팝업 표시
  ↓
팝업 확인 시: 해당 지점 탭 삭제 처리
```

팝업 확정 문구:
```
"접근 권한의 변경이 발생했습니다.
더 이상 접근할 수 없는 지점이 있습니다.
운영 담당자에게 문의해 주세요."
```

> ⚠️ 미확정: 권한 변경 정보를 화면에 전달하는 방식 (WebSocket push vs polling vs API 에러 감지) 미확정.
